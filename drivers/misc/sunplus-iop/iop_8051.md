# SP7021 8051 IOP Driver — Technical Notes

## Hardware Overview

The SP7021 SoC contains an 8051 microcontroller called the **IOP (IO Processor)**. It
manages low-power states, GPIO in standby, RTC wake-up, and the power sequencing needed
to cut power to the ARM Default domain on `poweroff`.

### Power domains

| Domain | Contents | Powered in S3 |
|--------|----------|---------------|
| Default | ARM cores, most peripherals | No |
| IOP | 8051 core, IOP SRAM | No (cut by S3_Mode) |
| AO (Always-On) | RTC, wake circuitry, some GPIO | Yes |

### Physical SRAM

The 8051 executes firmware loaded into a 1 MB SRAM at physical address **0x100000**.

**Critical**: This is the same physical address the ARM kernel relocates itself to at
boot (TEXT_OFFSET = 0x208000, so kernel .head.text is at 0x208000 and .text at 0x300000,
but the SP7021-specific TEXT_OFFSET = 0x208000 was chosen to place the kernel above the
IOP SRAM range 0x100000–0x1FFFFF).

See `arch/arm/Makefile`: `textofs-$(CONFIG_ARCH_SUNPLUS) := 0x00208000`

### Firmware sizes

| Firmware | Size | Purpose |
|----------|------|---------|
| iop-normal.bin | 64 KB | Normal operation (I2C slave, GPIO blink) |
| iop-standby.bin | 16 KB | Poweroff/S1 handshake with ARM |

Standby firmware is limited to 16 KB because it must fit in the 8051 ICache (which
retains content when IOP SRAM power is cut in S1 mode).

## Firmware Routing Register

The IOP maps its code space from an ARM physical address set via `iop_base_adr_l/h`.
The value written is the physical base address (`0x100000`).

**Important**: The routing register value for GPIO_INT lines (used elsewhere in the
driver) is 0-indexed from GPIO pin 7. Write `(pin - 7)`, not the raw pin number.

---

## Reset Mechanism

- `iop_control` bit 0: IOP CPU reset — **read-modify-write** (NOT Moon-format)
- `MOON0_RESET0` bit 4: IOP hardware IP reset — **Moon-format** (`0x00100010` to assert,
  `0x00100000` to release)
- `MOON0_CLKEN0` bit 4: IOP clock enable — **Moon-format** (`0x00100010`)

The Moon register write format: bits `[31:16]` = write-enable mask, bits `[15:0]` = data.
Only bits whose mask bit is set are written.

The `MOON1_CLKEN0` write during powerdown must use individual bit masks
(`0x00850085` = set bits 7, 2, 0 only) rather than the broad mask `0x00ff0085` which
also clears bits 1, 3, 4, 5, 6 — those bits control secondary ARM CPU clocks and clearing
them takes CPUs offline mid-shutdown, causing RCU stalls.

---

## Poweroff Handshake Protocol

ARM side:
1. Load standby firmware to SRAM; flush D-cache to physical RAM
2. Reset 8051 via `iop_pmc_setup` (Moon0 IP reset + iop_control)
3. Poll `iop_data2 & IOP_READY (0x04)` — 8051 sets this when ready
4. Write `RISC_READY (0x08)` to `iop_data2`
5. Write `0x00` to `iop_data5`, `0x60` to `iop_data6`
6. Poll `iop_data7 == 0xaaaa`
7. Write `0xdd` to `iop_data1` → triggers `S3_Mode()` on 8051

8051 side (standby firmware):
1. `wakeup_check_by_interrupt()` — exits if no PMC IR/RTC latch
2. Set `IOP_DATA2_L = 0x04` (IOP_READY)
3. Wait for RISC to set `iop_data5 = 0, iop_data6_L = 0x60`
4. Set `IOP_DATA7 = 0xaaaa`
5. Read command from `IOP_DATA1_L`:
   - `0xdd` → `Fill_ICache(); S3_Mode()` (AO on, Default+IOP off)
   - `0xee` → `Fill_ICache(); S1_Mode()` (AO+IOP on, Default off)

`Fill_ICache()` reads the entire 16 KB standby code area into ICache so the 8051 can
continue executing after IOP SRAM power is cut.

## S3_Mode() Power Sequence

The `S3_Mode()` function in `standby_main.c` writes to `POWER_CONTROL` (SFR 0xF4) and
`POWER_GATE` (SFR 0xF5):

```c
POWER_CONTROL |= (1 << Isolation_bit);       // isolate Default domain
wait_1ms(50);
POWER_GATE    &= ~(1 << REG_IOP_PWR_GATE_bit); // internal regulator
wait_1ms(50);
POWER_CONTROL |= (1 << DEF_PWR_EN_OE_bit);  // PWR_EN output enable
POWER_CONTROL &= ~(1 << DEF_PWR_EN_O_bit);  // PWR_EN low
POWER_GATE    |= MO_DC_12/15/09 ENB bits;   // enable DC-DC converters
wait_1ms(10);                                 // settle (absent in older source)
POWER_CONTROL |= (1 << IOP_PWR_DWN_bit);    // cut IOP power
```

The `wait_1ms(10)` before `IOP_PWR_DWN_bit` was identified by disassembling the original
Keil-compiled binary and comparing with the SDCC output. The Keil binary includes this
delay; the source as-shipped did not. Without it, `S3_Mode()` fails to cut power.

## SDCC Build Notes

### Toolchain

```bash
sudo apt-get install sdcc srecord
```

### Startup fix

SDCC 4.x requires `__sdcc_external_startup` or the linker exits with error 1.
Fix in `startup/crtstart.asm`: replace `lcall __sdcc_external_startup` + conditional
branch with `sjmp __sdcc_init_data` to always proceed with normal initialisation
(clear BSS, copy DATA). Without this fix, global variables are uninitialised and
firmware is unreliable.

### Build commands

```bash
cd /home/ag/src/sunplus/SP7021/firmware/iop

# Normal firmware (64 KB)
make STANDBY=0       # ignore exit code 1 from linker warning
packihx __build/dq8051_firmware.ihx > __build/normal.hex
srec_cat __build/normal.hex -Intel -byte-swap 4 --fill 0xff 0 65536 \
  -o __build/iop-normal.bin -Binary

# Standby firmware (16 KB)
make STANDBY=1
packihx __build/dq8051_firmware.ihx > __build/standby.hex
srec_cat __build/standby.hex -Intel -byte-swap 4 --fill 0xff 0 16384 \
  -o __build/iop-standby.bin -Binary
```

The `-byte-swap 4` flag reorders bytes within each 4-byte word to match ARM
little-endian memory layout for the 8051's sequential byte fetch.

## GPIO (sys-red LED)

GPIO 18 is configured as IOP-controlled via `SPPCTL_PCTL_G_IOPP` in the
`pins_gpio_nobinded` pinctrl state (`fdl-sp7021-84.dts`). This sets FIRST=1 (GPIO mode)
and MASTER=0 (IOP control) at boot without needing any ioremap in the IOP driver.

Normal firmware: GPIO controlled by ARM's gpio-leds driver (sys-red is removed from
the LED node and left to the IOP).

Standby firmware: LED driven solid red while waiting for ARM handshake, then turned off
just before `S3_Mode()` cuts power. The LED going off = board powered down.

---

## Firmware Loading

Firmware is loaded via `request_firmware()` using `CONFIG_EXTRA_FIRMWARE`:

```
CONFIG_EXTRA_FIRMWARE="sunplus/iop-normal.bin sunplus/iop-standby.bin"
CONFIG_EXTRA_FIRMWARE_DIR="firmware"
```

This embeds the binaries into the kernel image via the standard firmware loader
infrastructure, making them available at probe time without needing the rootfs mounted.
The normal firmware starts the 8051 at probe time; the standby firmware is cached in
`kmalloc`'d memory for use during poweroff.
